# GunRaid — ход работ

Журнал по этапам из [плана](roadmap.md): что готово, как проверить, что осталось.

## Этап 1 — каркас ✅

- Монорепо pnpm + Turborepo, TypeScript 6 strict, ESLint (кириллица в коде фронта запрещена — только i18n), Prettier, GitHub Actions CI.
- `docker compose up --build` → http://localhost:8080 (Caddy: сайт, `/api`, `/socket.io` на одном домене). Контейнер `migrate` применяет миграции и идемпотентные сиды.
- Вход: Steam OpenID, Google OAuth (PKCE), Telegram Login Widget, тестовый вход (только `AUTH_DEV_LOGIN=true` и не `APP_ENV=production`). Привязка нескольких способов к одному аккаунту, отвязка (кроме последнего).
- Сессии: access JWT 15 мин + refresh 30 дней с ротацией и обнаружением повторного использования; «выйти со всех устройств» действует сразу (Redis). CSRF double-submit. Rate limit (Redis). Роли user / support / admin. Подтверждение 18+ с датой и IP.
- Игра в URL (`/standoff2`, `/cs2`), cookie и профиль. Хедер, мобильный таб-бар, футер, лента дропов (место), онлайн по WebSocket.
- Дизайн-система: токены, рубленые углы, шрифты Tektur + Golos Text, `GemIcon` / `GemAmount`, витрина `/dev/ui`.

## Этап 3 — кейсы, provably fair, лента дропов ✅

- `packages/game-core` — общая для сервера и браузера логика: HMAC-SHA256 (server seed, client seed, nonce), 52 бита → число [0, 1), билет × 10 000 000, выбор предмета по накопленным шансам, RTP, подбор шансов под целевой RTP.
- Кейсы: категории (популярные, премиальные, лимитированные, бесплатные, за уровень), неизменяемые ревизии состава (старые результаты проверяются и после правки кейса), открытие x1–x5, бесплатные кейсы с кулдауном и по уровню, лимитированные с атомарным счётчиком тиража и обновлением по WebSocket. 16 демо-кейсов с RTP 0,90 (лимитированные — 0,92).
- Пары сидов на пользователя: server seed зашифрован AES-256-GCM, хэш показывается заранее, смена пары раскрывает старый сид; client seed меняется вместе с парой.
- Страница кейса: рулетки (несколько линий для x2–x5), «быстро», звук (синтез Web Audio, без сторонних файлов), окно результата: продать один / всё, оставить, открыть ещё, ссылка на проверку.
- Provably Fair: объяснение и формула, своя пара сидов, история раскрытых сидов, проверка любого результата в браузере тем же кодом (`/provably-fair?opening=<id>`).
- Лента live-дропов: событие пишется в outbox в транзакции открытия, воркер публикует его с задержкой на длительность анимации (`settings.feed.delayMs`) в Redis и в комнату Socket.IO; счётчик открытых кейсов.
- Тесты: проверка результатов по раскрытому сиду, x3 = три nonce подряд, баланс на 3 открытия → ровно 3 из 10 параллельных, кулдаун бесплатного кейса (1 из 5 параллельных), тираж (2 из 5 игроков, остальным не списано), уровень, идемпотентность, outbox → лента.

## Этап 4 — апгрейд и контракт ✅

- **Апгрейд** (`/<игра>/upgrade`): ставка предметами (до 10) или гемами с баланса → предмет из каталога. Шанс = ставка / цена цели × (1 − комиссия), не выше максимума (`settings.upgrade`: комиссия 10 %, максимум 75 %, минимум 1 %). Кнопки x1.5 / x2 / x5 / x10 подбирают ближайшую по цене цель, поиск по каталогу. Шанс и бросок хранятся целыми в миллионных долях; победа — если бросок меньше шанса.
- Анимация: кольцо с сектором шанса и стрелка, которая останавливается на броске; «быстро» и звук; история апгрейдов.
- **Контракт** (`/<игра>/contract`): 3–10 предметов → один предмет из каталога. Множитель k = kMin + (kMax − kMin) · u^γ, где u — бросок provably fair; γ подобран так, что средний возврат = 1 − комиссия (0,25×–4×, комиссия 10 %: P(больше вложенного) ≈ 29 %). Выдаётся предмет с ценой, ближайшей к вложенное × k, в диапазоне [вложенное × kMin, вложенное × kMax].
- Обе операции — в одной транзакции: блокировки кошелька и предметов, списание через ledger или перевод предметов в статус «использован», бросок по паре сидов пользователя, выдача результата, запись в ленту дропов через outbox (с задержкой на анимацию). Идемпотентность по `Idempotency-Key`.
- Provably Fair: проверка апгрейдов и контрактов на `/provably-fair?upgrade=<id>` и `?contract=<id>` тем же кодом из `packages/game-core`.
- Исправлено: расхождение гидратации, когда сессия или настройки из localStorage становились известны до гидратации отложенных Suspense-блоков (`useMe` и `usePrefs` отдают серверное состояние до конца гидратации).
- Тесты: ставка гемами — шанс и результат сходятся с пересчётом по раскрытому сиду; предметы ставки списываются; цель дешевле ставки и слишком низкий шанс отклоняются; один предмет в параллельных апгрейдах участвует один раз; лимит числа предметов контракта; множитель контракта проверяется; параллельные контракты с одними предметами — проходит один.

## Этап 5 — кейс-баттлы в реальном времени ✅

- Форматы 1×1, 1×1×1, 1×1×1×1 и 2×2; режимы «Классика» (больше сумма — забирает всё) и Crazy (меньше — забирает всё). Набор кейсов с повторами (до `settings.battle.maxCases` = 25), стоимость участия = сумма кейсов. Для баттлов доступны обычные платные кейсы (без тиража, уровня и кулдауна).
- Лобби: создание с оплатой, вход на выбранное место (в 2×2 место = команда), заполнение ботами кнопкой создателя, отмена создателем и автоматическое закрытие через 30 мин — с возвратом всем участникам. Последнее место берёт ровно один игрок (блокировка строки баттла; порядок блокировок: кошельки → баттл).
- Старт — в той же транзакции, что и вход последнего участника: фиксируется client seed баттла = SHA-256 от client seed участников по местам (у ботов — сид из браузера создателя), считаются все броски `HMAC(serverSeed, "clientSeed:раунд:место")`, победитель и распределение. Server seed баттла свой, его хэш виден с момента создания, сам seed — после завершения.
- Синхронные рулетки: воркер по расписанию (outbox) присылает результат раунда в комнату `battle:<id>` за 1 с до `spinStartAt`; браузер стартует вертикальные рулетки по серверным часам (смещение — из `time:sync`), опоздавший подхватывает анимацию с нужного места. API тоже показывает раунд только с момента его вращения. Обратный отсчёт 3 с, раунд 6 с (настройки).
- Выдача выигрыша — воркером после последнего раунда: победитель получает все предметы; в 2×2 каждый победитель — свои дропы и дропы соперника из парного места (вариант А). Если победил бот — предметы остаются у сайта. Проигравшим — запись «Проигран в баттле» в истории дропов. Ничья — дополнительный бросок provably fair.
- Интерфейс: список активных лобби в реальном времени с фильтрами (формат, режим), история и «Мои», конструктор баттла, комната с раундами, итогом, повтором и ссылкой на проверку; лента live-дропов получает дропы игроков после остановки рулетки; в профиле — счётчик выигранных баттлов.
- Provably Fair: `/provably-fair?battle=<id>` — пересчёт client seed из сидов участников, каждого раунда и победителя в браузере.
- Оплата входа — гемами. Вариант «участвовать скинами» из предложений этапа 0 не делал: предметы продаются в инвентаре в один клик, отдельная механика не нужна (если понадобится — добавлю).
- Тесты: создание и отмена (двойная отмена возвращает деньги один раз), чужая отмена и недоступные кейсы, нехватка баланса; из 6 параллельных входов на последнее место проходит один; повтор входа с тем же ключом списывает один раз; боты + выдача (повторная выдача — no-op) + проверка всех раундов по раскрытому сиду; crazy; распределение 2×2; таймаут лобби с возвратом; раскрытие раундов по времени и отсутствие предметов до конца баттла. Unit-тесты победителя, ничьей и распределения в `game-core`.

## Этап 6 — бонусы ✅

- **Колесо фортуны** (`/<игра>/bonuses`): бесплатное вращение раз в 24 ч (кулдаун общий на аккаунт), доп. вращения по бонусам. Призы с весами в таблице `wheel_prizes` (на игру): гемы, предмет, бесплатный кейс, бонус к пополнению, доп. вращение. Антиабуз (настройки `wheel`): аккаунт старше 24 ч и пополнение за последние 30 дней. Результат — provably fair по паре сидов игрока, набор весов сохраняется с вращением; проверка на `/provably-fair?wheel=<id>`. SVG-колесо с анимацией до выпавшего сектора, звук, история призов.
- **Промокоды**: гемы, бонус к пополнению (%, потолок), бесплатный кейс, вращение колеса, предмет. Ограничения: общий лимит активаций (под блокировкой строки — не превышается при параллельных запросах), лимит на пользователя, срок, минимальное пополнение за период, привязка к игре, «только для новых». Привязка к партнёру-блогеру (`partners`; статистика — в админке на этапе 7). IP и устройство активации сохраняются. Поле промокода — в разделе бонусов и в окне пополнения.
- **Права (бонусы)** `user_entitlements`: бесплатное открытие кейса (кнопка «Открыть бесплатно» на странице кейса, одно право — одно открытие даже при параллельных запросах), доп. вращение, бонус к пополнению (лучший из активных применяется автоматически, показывается в котировке до оплаты, тратится при зачислении).
- **Ежедневный бонус** со стриком: 5 → 10 → 15 → 20 → 25 → 30 → 50 гемов, пропуск дня обнуляет серию; «день» — по часовому поясу сайта (UTC+3).
- **Уровни и XP**: 1 XP за каждый гем, поставленный в кейсах, апгрейдах, контрактах и баттлах (событие `wager.placed` в outbox → воркер). 50 уровней (порог 100 × (L−1)^2,2 XP), награда за каждый уровень (гемы; каждый 5-й — вращение колеса, каждый 10-й — бонус к пополнению) выдаётся ровно один раз.
- **Рефералы**: 5 % от каждого пополнения приглашённого (настройка `referral.percent`), идемпотентно по пополнению; ссылка, статистика и начисления — в бонусах и профиле.
- **Лидерборды** (`/<игра>/leaderboard`): день и неделя, топ-20 по сумме дропов из режимов, моя позиция, призы по местам (таблица `leaderboards`), победители прошлого периода. Воркер раз в минуту подводит итоги завершившихся периодов и начисляет призы (повторный запуск ничего не дублирует).
- **Достижения**: 12 штук с иконками (условия из набора типов, параметры в БД), прогресс и дата получения во вкладке профиля; пересчёт в воркере по событиям игрока.
- **Уведомления** (колокольчик в шапке): пополнение, новый уровень, достижение, итог баттла, приз лидерборда, реферальное начисление; новые приходят по WebSocket.
- Демо-данные: призы колеса для обеих игр, промокоды `GUNRAID` (100 гемов, партнёр «Демо-блогер»), `BONUS10` (+10 % к пополнению), `FREECASE` (бесплатный кейс CS2), `SPIN` (вращение), `NEWBIE` (для новых), `SKINSO2` (предмет Standoff 2). У DevPlayer есть тестовое пополнение и «стаж» 30 дней — колесо доступно сразу.
- Тесты: ежедневный бонус (из 3 параллельных — один, продолжение стрика), колесо (условия, из 4 параллельных вращений — одно, доп. вращение, проверка по раскрытому сиду), промокоды (общий лимит при 4 параллельных активациях, лимит на пользователя, срок, игра, условие пополнения, бонус к пополнению применяется один раз), бесплатный кейс по бонусу (из 3 параллельных — одно, без списания), XP и награды за уровни один раз, реферальное начисление один раз, итоги лидерборда один раз с призами и уведомлением, достижения и прочтение уведомлений.

## Этап 7 — вывод (заглушки) и админка ✅

- **Вывод предметов** (гемы не выводятся): кнопка «Вывести» в инвентаре, окно с условиями и инструкцией по игре, вкладка «Выводы» в профиле с историей статусов. Заявка блокирует предмет (статус «на выводе»); при отказе, неудаче, отмене, таймауте или отмене сделки предмет возвращается в инвентарь.
- `WithdrawalProvider`: **CS2 — заглушка P2P-маркета** (явно помечена в интерфейсе и админке): одобрение → покупка → оффер обмена → обмен принят → период защиты 7 дней (сделку можно «отменить» — предмет вернётся) → завершено (воркер). События маркета имитируются кнопками в админке. **Standoff 2 — ручной поток**: оператор одобряет и назначает цену лота в золоте, игрок выставляет лот и указывает его номер (таймаут 30 мин → «время вышло»), оператор подтверждает покупку.
- Антифрод (настройки `antifraud`): вывод не раньше суток после первого пополнения, минимум пополнений для вывода, суточный лимит для аккаунтов младше 7 дней; флаги «подозрительный», «новый аккаунт», «общее устройство» в очереди. Автоматических банов нет.
- **Админка** `/admin` (роль проверяется при рендере на сервере и в API на каждом запросе; support — пользователи и выводы, admin — всё):
  - дашборд: пользователи, пополнения, выводы, выданные бонусы, GGR, фактический RTP по режимам против целевого, результат сверки ledger;
  - пользователи: поиск, карточка (способы входа, профили игр, статистика, ledger, входы с IP и устройствами, связанные аккаунты по общим IP/устройствам), корректировка баланса только через ledger с обязательной причиной, бан/разбан (сессии отзываются сразу), флаг «подозрительный», смена роли;
  - очередь выводов, пополнения, журнал аудита всех действий;
  - кейсы: создание и редактирование (цена, категория, картинка, цвет, тираж, уровень, кулдаун, период доступности), редактор состава с шансами в процентах, контролем суммы 100 %, RTP и ожидаемой стоимостью в реальном времени, подбором шансов под целевой RTP; сохранение — новая неизменяемая ревизия;
  - каталог: цены и флаги предметов (активен, вывод, апгрейд, контракт), массовое изменение цен по фильтру, редкости (название, цвет, порядок), импорт CSV и обновление цен;
  - бонусы: призы колеса с весами и вероятностями, промокоды (все типы и ограничения), партнёры со статистикой, уровни и награды, призы лидербордов, достижения;
  - настройки: все группы (курс гемов, комиссии апгрейда и контракта, параметры баттлов, колеса, ежедневного бонуса, рефералов, антифрода, вывода…) и курсы валют пополнения — без правки кода.
- Тесты: условия вывода, из 3 параллельных заявок на один предмет — одна, поток CS2 со «отменой сделки» и возвратом, завершение после периода защиты (воркер), Standoff 2 с ценой в золоте, лотом и подтверждением, таймаут лота с возвратом, отмена игроком, аудит отказа; админка — корректировка баланса (причина, идемпотентность, сверка, аудит), права support, бан, настройки с валидацией, новая ревизия кейса и открытие по ней, дашборд.

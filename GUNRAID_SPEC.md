# GunRaid — техническое задание для Claude Code

## 0. Как работать с этим ТЗ

Ты — ведущий full-stack разработчик. Нужно построить с нуля сайт **GunRaid**: сервис открытия кейсов, апгрейдов, контрактов и кейс-баттлов со скинами для двух игр — **Standoff 2** и **CS2**. Референс по функциональности и UX — сайты вроде ggstandoff (ggstand.com), но дизайн и код полностью свои.

Порядок работы:
1. **Сначала ничего не пиши в коде.** Изучи ТЗ целиком, затем предложи: стек, архитектуру, структуру репозитория, схему БД (таблицы и связи), список API и план по этапам из раздела 15. Дождись моего подтверждения.
2. Дальше работай строго по этапам. В конце каждого этапа: проект запускается одной командой, тесты зелёные, сделан коммит, коротко отчитайся, что готово и что дальше.
3. Если чего-то не хватает для решения (данные, ключи, бизнес-правило) — **спроси меня**, не придумывай значения и не оставляй молча заглушки. Технические заглушки допустимы только там, где это прямо разрешено в ТЗ (платежи, вывод), и они должны быть явно помечены.
4. Пиши так, чтобы проект можно было вести долго: типизация, миграции, сиды, тесты на бизнес-логику, понятные модули.

## 1. Продукт в двух словах

- Пользователь пополняет баланс во внутренней валюте сайта — **гемах** (пока — тестовый провайдер; см. раздел 12.1), открывает кейсы, получает скины в инвентарь.
- Скины можно продать обратно за баланс, вывести в игру, использовать в апгрейде или контракте, участвовать ими/балансом в кейс-баттлах.
- Две игры в одном сервисе. Выбор игры — в хедере, он переключает весь каталог: кейсы, предметы, инвентарь, режимы.
- Язык интерфейса — **только русский**, но вся строка-текстовка через i18n-ключи, чтобы позже добавить языки без переделок.
- Аудитория в основном с телефонов → **mobile-first**, всё должно быть удобно на экране 360px.

## 2. Требования к стеку (выбор стека — за тобой)

Выбери стек сам и обоснуй выбор в первом ответе. Обязательные требования:
- TypeScript на фронте и бэке.
- PostgreSQL как основная БД, миграции, сиды с демо-данными.
- Redis (кэш, очереди, rate limit, pub/sub для real-time).
- Real-time через WebSocket: лента дропов, баттлы, онлайн, уведомления.
- Весь проект поднимается локально одной командой (docker compose), есть `.env.example` со всеми переменными.
- SSR/SEO для публичных страниц (главная, кейсы, страницы кейсов, FAQ, правовые страницы).
- Админка — часть проекта (отдельный раздел с ролями), не отдельный продукт.

## 3. Бренд и дизайн

- Название: **GunRaid**. Логотип и брендовые файлы я положу в `assets/brand/` — до этого используй текстовый плейсхолдер и спроси меня о файлах на этапе дизайна.
- Цвета: фон near-black `#0B0B0F`, акцент лайм `#C6FF00`, белый текст, серые поверхности (оттенки `#15151B`–`#24242E`).
- Стиль: тёмный, агрессивный геймерский, рубленые углы (скошенные кнопки и карточки), жирный угловатый шрифт для заголовков, читаемый гротеск для текста. Лайм — только для акцентов и CTA.
- Цвета редкостей — отдельная палитра, задаётся в конфиге редкостей (раздел 5).
- Иконка внутренней валюты (гема) и правила показа сумм — раздел 12.1.
- Анимации: рулетка открытия кейса, спиннер апгрейда, анимация контракта, синхронные рулетки в баттле, колесо фортуны. Везде есть кнопка «быстро» (пропуск анимации) и переключатель звука.
- Не использовать логотипы, шрифты и фирменные изображения Valve и Axlebolt.

## 4. Игры и переключатель игры

- Две игры: `standoff2` и `cs2`. Модель данных сразу рассчитана на добавление новых игр.
- Переключатель в хедере (иконка + название игры). Выбор сохраняется (cookie + профиль) и отражается в URL (`/standoff2/...`, `/cs2/...`), чтобы ссылки на кейсы были шарируемыми.
- Баланс у пользователя **один общий**, инвентари и каталоги — **раздельные по играм**.
- Каждая страница, режим и запрос к API учитывают выбранную игру.

## 5. Предметы и редкости

### Каталог предметов
Поля предмета: игра, тип (оружие / нож / перчатки / наклейка / брелок / граффити и т.п.), модель оружия, название скина, полное название, редкость, коллекция, изображение, цена (в гемах, см. 12.1), флаги StatTrak/Souvenir где применимо, для CS2 — износ (FN/MW/FT/WW/BS) и диапазон float, флаг «доступен к выводу».

- Страница «Все предметы» по выбранной игре: сетка карточек, фильтры (редкость, тип, модель оружия, диапазон цены, StatTrak), сортировка, поиск, пагинация/бесконечный скролл.
- Страница предмета: изображение, редкость, цена, в каких кейсах встречается и с каким шансом.
- Импорт каталога и цен: CSV-импорт через админку + интерфейс `PriceProvider` для будущей автоматической загрузки цен (сейчас — заглушка, читающая из БД/CSV). Сиды: по 40–60 демо-предметов на игру с плейсхолдер-картинками, чтобы всё было кликабельно.

### Редкости — конфиг по игре
Редкости хранятся в таблице (игра, код, название, цвет, порядок), а не в коде.
- CS2 (сид): Ширпотреб, Промышленное качество, Армейское качество, Запрещённое, Засекреченное, Тайное, Контрабанда, ★ Редкий особый предмет (ножи/перчатки).
- Standoff 2: **спроси меня актуальный список редкостей и цветов перед сидом**, не заполняй по памяти.

## 6. Аутентификация и аккаунт

- Вход: **Steam (OpenID)**, **Google (OAuth)**, **Telegram (Login Widget)**. Один аккаунт можно привязать ко всем трём.
- Для вывода CS2 нужен привязанный Steam и сохранённая trade-ссылка (валидация формата).
- Для вывода Standoff 2 нужен игровой ID Standoff 2 в профиле.
- Сессии с refresh, выход со всех устройств, роли: user, support, admin.
- Подтверждение 18+ при первом входе (чекбокс и запись в БД с датой).

## 7. Профиль

- Шапка: аватар, ник, уровень и прогресс XP, дата регистрации, привязанные аккаунты.
- Статистика: открыто кейсов, сумма пополнений, лучший дроп (карточка), выигранные апгрейды/контракты/баттлы.
- Вкладки истории: дропы, апгрейды, контракты, баттлы, пополнения, выводы, активированные промокоды, бонусы.
- Настройки: trade-ссылка CS2, ID Standoff 2, звук, быстрый режим по умолчанию, client seed (provably fair).
- Публичный профиль других игроков (ник, уровень, лучший дроп, последние дропы) — открывается по клику из ленты дропов.
- Реферальный блок: личная ссылка/код, число рефералов, начисленный доход.

## 8. Инвентарь

- Раздельный по играм, переключение через выбранную игру.
- Статусы предмета: в инвентаре, продан, на выводе, выведен, использован в апгрейде, использован в контракте, проигран в баттле.
- Действия: продать (один / выбранные / все), вывести, отправить в апгрейд, добавить в контракт.
- Мультивыбор, сортировка по цене/редкости/дате, итоговая сумма выбранного.
- Предметы, выигранные в кейсе, можно продать прямо в окне результата.

## 9. Режимы

### 9.1 Кейсы
- Главная: категории кейсов (обычные, по уровню/званию, лимитированные с тиражом и счётчиком, бесплатные/ежедневные), баннеры, лента дропов.
- Страница кейса: цена, содержимое с редкостями, ценами и **шансами в процентах**, кнопки открытия x1–x5, «быстро», рулетка.
- После открытия: продать / оставить / открыть ещё.
- Бесплатный кейс: доступен по уровню или раз в N часов, с кулдауном.
- Для каждого кейса админка показывает ожидаемую доходность (RTP) по текущим ценам и шансам.

### 9.2 Апгрейд
- Слева выбираешь 1+ предметов из инвентаря **или** сумму с баланса, справа — целевой предмет из каталога.
- Шанс = ставка / цена цели × (1 − комиссия апгрейда), с ограничением максимального шанса (комиссия и максимум — настройки в админке).
- Быстрые кнопки множителей (x1.5, x2, x5, x10) подбирают цели.
- Круговой спиннер с отображением шанса, результат — выигрыш целевого предмета или потеря ставки.

### 9.3 Контракт
- Кладёшь от 3 до 10 предметов одной игры.
- Показывается сумма вложенного и диапазон возможного результата (минимум–максимум, коэффициенты — настройки).
- Результат — один предмет из каталога, подобранный по выпавшему значению в этом диапазоне.
- Анимация «переплавки», история контрактов.

### 9.4 Кейс-баттлы
- Создание лобби: 2, 3 или 4 игрока, режим 2×2, выбор набора кейсов (можно несколько разных и повторы), стоимость участия = сумма кейсов.
- Режимы: классический (больше суммарный дроп — забирает всё), «crazy» (меньше — забирает всё).
- Свободные места можно заполнить ботами (кнопкой создателя).
- Все рулетки участников крутятся синхронно в реальном времени, раунд за раундом.
- Список активных баттлов с фильтрами, история, страница завершённого баттла с повтором.
- Каждый раунд проверяем через provably fair.

## 10. Бонусы

### 10.1 Колесо фортуны
- Бесплатное вращение раз в N часов (кулдаун с таймером).
- Призы настраиваются в админке: баланс, конкретный предмет, бесплатный кейс, бонус к пополнению (%), дополнительное вращение. Вес каждого приза задаётся в админке.
- Антиабуз: условия доступа (например, минимальный депозит за период или возраст аккаунта) — настраиваются.
- Красивая анимация вращения, история выигрышей.

### 10.2 Промокоды
- Типы: начисление баланса, бонус к пополнению в %, бесплатный кейс, вращение колеса, предмет.
- Ограничения: общий лимит активаций, лимит на пользователя, срок действия, минимальный депозит, привязка к игре, только для новых пользователей.
- Поле ввода промокода — в окне пополнения и в разделе бонусов.
- Промокоды блогеров: привязка кода к партнёру и статистика по нему в админке.

### 10.3 Остальные бонусы
- Бонус за первое пополнение.
- Ежедневный бонус со стриком.
- Уровни и XP за активность, награды за новые уровни.
- Реферальная программа: процент от пополнений рефералов, настраиваемый.

## 11. Ещё функции

- Лента live-дропов в верхней части сайта (real-time, клик → профиль игрока).
- Онлайн-счётчик, общая статистика сайта (кейсов открыто, пользователей).
- Лидерборды: топ за день/неделю по сумме дропов, с призами (настраиваются).
- Достижения (ачивки) с иконками в профиле.
- Уведомления (колокольчик): выводы, бонусы, результаты баттлов.
- Страница **Provably Fair**: объяснение, server seed (хэш показывается заранее, сам seed — после смены), client seed, nonce, инструмент проверки любого результата.
- FAQ, поддержка (кнопка с ссылкой на Telegram, контакт задаётся в конфиге).
- Правовые страницы: оферта, политика конфиденциальности, правила, 18+, ответственная игра. Тексты — плейсхолдеры, помеченные `TODO: юрист`.
- Cookie-баннер.

## 12. Деньги, пополнения и вывод (на этом этапе — тестовые)

- **Баланс — только через бухгалтерскую книгу (ledger).** Каждая операция (пополнение, открытие, продажа, апгрейд, контракт, баттл, бонус, вывод, корректировка админом) — запись с типом, суммой и ссылкой на сущность. Баланс = сумма записей; хранить денормализованный баланс можно, но он сверяется. Все операции — в транзакциях с блокировкой строк, идемпотентные (idempotency key).
- Суммы — целые числа в гемах (1 гем — минимальная единица). Внутренняя валюта и курс — раздел 12.1.
- `PaymentProvider` — интерфейс пополнения. Сейчас одна реализация `MockPaymentProvider`: имитирует успешный и неуспешный платёж, вебхук, подпись. Позже подключу реальные провайдеры (карты, крипта) — архитектура должна это позволять без переписывания.
- `WithdrawalProvider` — интерфейс вывода:
  - **CS2:** заглушка под P2P-маркет (позже — покупка скина на маркете с отправкой на trade-ссылку пользователя, статусы, обработка отмены сделки в течение 7 дней).
  - **Standoff 2:** ручной поток — пользователь выставляет на игровой рынок скин по цене выводимого предмета, оператор в админке подтверждает покупку. Статусы и таймауты.
- Вывод проходит через очередь со статусами и ручным подтверждением в админке.
- Антифрод-настройки: задержка вывода после первого пополнения, лимиты вывода для новых аккаунтов, флаг подозрительного аккаунта.

### 12.1 Внутренняя валюта — гемы

1. Внутренняя валюта сайта называется «гемы». Все цены, баланс, бонусы, выигрыши, призы колеса, промокоды и суммы в истории везде показываются только в гемах.
2. Курс фиксированный: 100 гемов = $1. Курс — настройка в конфиге, не хардкод.
3. Хранение: целые числа, 1 гем = минимальная единица. Никаких дробных гемов.
4. Иконка гема: граненый кристалл цвета `#C6FF00`, отдельный SVG-компонент. Ставится рядом с каждой суммой на сайте.
5. Склонение в интерфейсе через i18n: «1 гем», «2 гема», «5 гемов».
6. Курс всегда на виду: в окне пополнения («100 гемов = $1») и в подсказке при наведении/тапе на баланс. При пополнении в другой валюте (гривна, рубль, крипта) показывать, сколько гемов будет начислено, до подтверждения оплаты.
7. Гемы нельзя вывести деньгами — выводятся только предметы.

## 13. Честность, безопасность, нагрузка

- Все случайные результаты — только на сервере, по схеме provably fair (HMAC-SHA256: server seed + client seed + nonce). Клиент никогда не решает исход.
- Конкурентные операции (два открытия одновременно, двойной клик) не должны ломать баланс — покрыть тестами.
- Rate limiting на все игровые и платёжные эндпоинты.
- Защита от мультиаккаунтов: сохранение IP и отпечатка устройства, отметки в админке (без автоматических банов).
- Аудит-лог всех действий админов и всех изменений баланса вне игровой логики.
- Валидация всех входящих данных, защита от CSRF/XSS, безопасные куки.

## 14. Админка

- Дашборд: пользователи, пополнения, выводы, GGR, фактический RTP по режимам против целевого.
- Каталог: предметы, редкости, импорт CSV, массовое изменение цен.
- Редактор кейсов: состав, шансы (сумма = 100%, валидация), цена, категория, тираж, расчёт RTP в реальном времени при редактировании.
- Настройки режимов: комиссии апгрейда и контракта, максимальный шанс апгрейда, параметры баттлов.
- Бонусы: колесо (призы и веса), промокоды, уровни, реферальный процент, лидерборды.
- Пользователи: поиск, просмотр истории и ledger, бан, ручная корректировка баланса с обязательной причиной.
- Очередь выводов с подтверждением/отклонением.
- Роли: support видит пользователей и выводы, admin — всё.

## 16. Критерии готовности

- Проект поднимается одной командой, сиды дают рабочий сайт с демо-кейсами для обеих игр.
- Можно войти, переключить игру, пополнить тестово, открыть кейс, продать/вывести предмет, сделать апгрейд и контракт, сыграть баттл с ботами, крутить колесо, активировать промокод.
- Баланс в любой момент сходится с ledger, конкурентные тесты проходят.
- Любой результат проверяется на странице Provably Fair.
- Админка позволяет полностью настроить кейсы, бонусы и комиссии без правки кода.
- Всё удобно работает на телефоне.
